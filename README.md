# 卫星遥测缺口修复（Telemetry Gap Repair）

卫星过站后会出现一段长度为 `n` 的连续遥测整体丢失。本服务用两种修复源
A、B，以首尾相接的半开区间 `[start, end)` 覆盖整个缺口 `[0, n)`，求最小
成本的完整分段方案。

## 代价定义

- 缺口位置编号为 `0 … n-1`。位置 `k` 上使用源 A / B 的逐位置代价分别为
  `costs[k].a`、`costs[k].b`，取值均为 `0 … 1_000_000` 的整数。
- 两种源各有一次性的**段启用费** `fee_a`、`fee_b`（同样为
  `0 … 1_000_000` 的整数）。**每启用一段就收一次**：即使相邻两段使用同一
  种源，后一段仍要重新支付启用费。
- 一段 `[i, j)` 只能选择一种源 `s`，其成本为

  ```
  fee[s] + Σ costs[k].s,  k ∈ [i, j)
  ```

- 方案由若干 `[start, end)` 段组成，满足
  `0 = start₀ < end₀ = start₁ < … < end_m = n`，每段长度
  `1 ≤ end - start ≤ L`。方案总成本是各段成本之和。

## 输入 / 输出

`POST /solve`，普通 JSON：

```json
{
  "n": 5,
  "L": 3,
  "fee_a": 10,
  "fee_b": 3,
  "costs": [
    {"a": 1, "b": 4},
    {"a": 2, "b": 3},
    {"a": 5, "b": 1},
    {"a": 1, "b": 4},
    {"a": 2, "b": 2}
  ],
  "objective": "default"
}
```

`objective` 为可选项，可省略，或取：

- `"default"`（默认）：最小成本后，继续按默认的段数、末段起点、末段来源顺序裁决；
- `"continuity"`：先保证最低总成本，再依次最小化相邻段的修复源切换次数、总段数、末段起点、末段来源。首段不计切换；这些键完全并列时，沿用前缀自身的同序裁决。

非法 `objective` 返回 **HTTP 422**，响应体只含标准 `detail`。

返回：

```json
{
  "cost": 20,
  "segments": [
    {"start": 0, "end": 2, "source": "B"},
    {"start": 2, "end": 5, "source": "B"}
  ],
  "certainty": ["B_ONLY", "B_ONLY", "B_ONLY", "B_ONLY", "B_ONLY"]
}
```

`certainty` 按位置 0 … n-1 依次返回：

- `"A_ONLY"`：该位置只能由 A 的一段覆盖；
- `"B_ONLY"`：该位置只能由 B 的一段覆盖；
- `"EITHER"`：两种源都分别存在某个总成本等于全局最小值的完整合法方案覆盖该位置。

该判定只以“总成本达到全局最小值”为准，不应用段数、切换次数等次级裁决；因此同一请求省略 `objective`、显式 `"default"` 或 `"continuity"` 时，`certainty` 完全相同。`cost`、`segments` 仍按所选 `objective` 的既有规则裁决。

约束：`1 ≤ n ≤ 200000`、`1 ≤ L ≤ 4096`；所有代价 / 启用费为
`0 … 1_000_000` 的整数。`len(costs)` 必须等于 `n`。任何长度不符、数值
越界、非法 `L` 或类型错误都返回 **HTTP 422**，响应体只含标准校验错误
`detail`，不返回成本，也不返回任何局部分段。

## 递推与唯一方案

令 `dp[j]` 为覆盖 `[0, j)` 的最优方案。对每个终点 `j`，在源
`s ∈ {A, B}` 与起点 `i ∈ [j-L, j-1]`（且 `i ≥ 0`）上取候选

```
(dp[i].成本 + fee[s] + Σ_{k=i}^{j-1} costs[k].s,
 dp[i].段数 + 1, i, s)
```

候选严格按四元组的字典序比较，依次为：

1. 累计成本（最小）
2. 段数（最少）
3. 前驱下标 `i`（最小）
4. 源（A < B）

因此递推唯一确定最优方案，不含任何随机或实现相关的平局处理。

### continuity 模式

`objective="continuity"` 在所有最低成本方案之间依次比较：

1. 相邻段来源切换次数（首段不计）；
2. 段数；
3. 末段起点；
4. 末段来源（A < B）；
5. 若仍并列，递归沿用前缀方案的同一套顺序。

例如 `n=3, L=1, fee_a=fee_b=0, costs=[(0,0),(1,0),(0,1)]` 时，最低成本为 0：
默认模式得到 `ABA`；continuity 模式在 `ABA`（两次切换）与 `BBA`（一次切换）之间选择
`BBA`。

## 算法

对固定源 `s`，候选值可改写为

```
(dp[i].成本 - prefix_s[i]) + prefix_s[j] + fee[s]
```

其中 `prefix_s[j]` 是源 `s` 在 `[0, j)` 上的逐位置代价前缀和；与 `i`
相关的部分只有 `dp[i].成本 - prefix_s[i]`，而可行起点 `i` 恰好构成滑动
窗口 `[j-L, j-1]`。

实现为每个源维护一个**单调双端队列**，队列元素的键为

```
(dp[i].成本 - prefix_s[i], dp[i].段数, i)
```

- 窗口左沿滑出的队首直接淘汰；
- 入队时从队尾弹出键严格更大的元素（键相同则保留更小下标，以满足“前驱
  下标更小优先”的平局规则）。

每个下标每源入队 / 出队至多一次，整体复杂度 **O(n) 时间、O(n) 空间**
（优于 O(n log n) 要求），不逐终点枚举 `L` 个起点，也不调用任何优化求解
器。结果由前驱指针回溯重建，每段都可按上述递推独立重算并精确复现报告的
最优成本。

`continuity` 模式为“末段来源 A / B”分别保存前缀状态。每个新来源只从对应
末段来源的状态窗口转移；另外使用无来源哨兵仅生成首段，首段不增加切换数。
哨兵不会写入 A / B 状态窗口，回溯也只引用 continuity 自己的状态，因此不会
事后改写默认模式中已淘汰的前缀。每个 `(前一来源, 新来源)` 组合维护一个滑动
窗口；窗口键在最低成本外包含切换数和段数，跨窗口比较再使用末段起点、末段
来源和前缀完整裁决键。默认模式仍走独立的原有递推，比较键与结果保持不变。
两种模式在 `n=200000, L=4096` 下均为 **O(n) 时间、O(n) 空间**。

## 位置来源确定性

令：

- `prefix[i]` 为覆盖 `[0, i)` 的最低成本（不应用任何次级裁决）；
- `suffix[j]` 为覆盖 `[j, n)` 的最低成本；
- 全局最低成本为 `M = prefix[n] = suffix[0]`。

来源 `s` 的一段 `[i, j)` 能出现在某个全局最优方案中，当且仅当

```text
prefix[i] + fee[s] + Σ_{k=i}^{j-1} costs[k].s + suffix[j] == M
```

因为等号左侧的最优前缀、当前段、最优后缀可以拼接为一个完整合法方案；不等号的其他方向则由最优性排除。实现分别正向和反向用滑动窗口计算 `prefix` / `suffix`，再把前缀按转移键

```text
prefix[i] - prefix_s[i]
```

分桶。对每个终点 `j` 与来源 `s`，只需 O(1) 找到同一键桶中最左的可行起点 `i`：所有合格起点到 `j` 的覆盖并集就是 `[i, j)`。用差分数组合并这些覆盖区间，扫描一遍即可得到每位置 A / B 是否可能。

该过程不枚举切分，也不只重放某个胜出前驱；段数、切换次数等 objective 的次级裁决不会改变全局最优方案集合。`n=200000、L=4096` 时仍为 **O(n) 时间、O(n) 空间**。

## 运行

要求 Python 3.12（或用 Docker）。

本地：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Docker Compose：

```bash
docker compose up --build          # 宿主端口默认 8000
API_PORT=9000 docker compose up    # 用 API_PORT 覆盖宿主端口
```

容器以非 root 用户 `appuser`（uid 10001）运行。

## 一次性验收

`verify` 是一次性服务，运行 pytest 后退出：

```bash
docker compose run --rm verify
```

## 测试

`tests/test_solver.py` 包含：

- `n ≤ 8` 的小规模预言机会枚举全部合法切分与 A/B 来源，并分别核对
  `default`、`continuity` 的完整递归裁决；
- 独立小规模预言机枚举所有达到全局最低成本的完整合法方案，逐位置核对来源
  并集；另锁定 `n=3、L=2、fee_a=fee_b=0`、
  `costs=[(0,5),(0,0),(5,0)]` 时返回
  `["A_ONLY","EITHER","B_ONLY"]`，且两个 objective 完全一致；
- `n = 3, L = 1`、费用全零、`costs=[(0,0),(1,0),(0,1)]` 锁定默认 `ABA`、
  continuity `BBA`；
- 随机小规模 / 中规模对拍，以及 `n = 200000`、`L = 4096` 的两种模式最大
  规模用例；continuity 与独立的惰性删除堆参考实现逐段比对，并校验时限；
- `n = 200000`、`L = 3` 时默认模式与朴素 O(nL) 递推对拍；
- 对每个返回方案按代价定义直接重放，断言恰好等于返回成本，且分段首尾相
  接、长度合法；
- 省略 `objective` 与显式 `"default"` 的 `cost`、`segments` 完全一致；
- 长度不符、越界、非法 `L`、非法 `objective`、错误类型、缺字段均返回
  422 且响应体只含标准 `detail`。
